threading model candidates:

-- asio io_service (global asynchronous multi thread pool)
	pros:
		* scales well as the total thread count can be fixed
		* network uses io_service anyhow
	cons:
		* object destruction is harder to manage

-- asio io_service per storage (per storage asynchronous multi thread pool)
	pros:
		* easier to handle destruction than in global io_service
		* highly concurrent
	cons:
		* excessive thread usage

-- single thread per storage
	pros:
		* easier to program (destruction)
	cons:
		* does not scale well with many storages
		* requires potentially extra thread jump because networking using io_service

-- event queue (global single thread)
	pros:
		* very easy programming model, not many locks needed
	cons:
		* scales very poorly
		* requires potentially extra thread jump because networking using io_service
