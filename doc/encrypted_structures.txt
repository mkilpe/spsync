
needs to support following changes:

* data changes
* user changes
* segment end points

All of these changes should form a chain of blocks which can be traversed and proven authentic.

consider:
* forward security
* backward security
* malleability
* segment end points to avoid checking full history and protecting the changes

Access structure:
list of members:
	* key id
	* access rights (read/write/admin)
	* encrypted symmetric keys
	* do we need meta data for members -- yes

All structures in chain have:
	* client last seen seq
	* seq from server
	* signature/tag

Chain of structures:

- Root block: -- consider how to authenticate the root block //should this just be user change? -- yes
	* sequence
	* Access structure
	* iv for encrypted data and key id
	* encrypted meta data (like rules, e.g. force signature instead of tag)
	* signature/tag

- User change:
	* sequence
	* Access structure
	* iv for encrypted data and key id
	* encrypted meta data
	* signature/tag

- Object change:
	- single change
		* sequence
		* object id
		* iv for encrypted data and key id
		* encrypted header
		* signature/tag

	- aggregated change
		* sequence
		* list of object ids
		* iv for encrypted data and key id
		* encrypted header
		* signature/tag

- segment end:
	* sequence
	* start and end seq
	* list of objects tags
	* iv for encrypted data and key id
	* encrypted meta data
	* signature/tag
