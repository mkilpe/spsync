The server last seen is always the last sequence we received from server.
The previous tag is the last record tag we know of, even uncommitted one.
Server has to check the previous tag is valid, ie. it belongs to a record that has been committed.


Don't build sequence on client side but rather only sign the records and let the server build the blockchain on the server side and push to clients
 * we do this to get sensible speed for committing records (i.e. the client doesn't need to always be totally up-to-date when committing which could leave to bad performance and starvation of slower clients)

block chain structure:

- block:
	* record
	* hash of the previous block
	* sequence number
